# kubectl-mcp-server's own dependency pin on fastmcp (fastmcp>=3.0.0b1) has
# no upper bound, but every fastmcp 4.x release drops `ToolAnnotations` from
# `fastmcp.tools`, which kubectl_mcp_tool's own code imports directly - an
# unpatched install can't start the tool at all. setup.sh patches the
# installed fastmcp package to restore that import, so fastmcp can stay on
# its own current upper bound here instead of being pinned back to <4.
# kubectl-mcp-server itself is still pinned exactly, matching
# platformfix/podium's Dockerfile (confirmed working there 2026-09-03;
# re-confirmed directly against this repo's own kind cluster while building
# it) - so a new kubectl-mcp-server release can't reintroduce a break like
# that one silently. Dependabot (pip ecosystem) will open a PR to review
# instead.
kubectl-mcp-server==1.24.0
fastmcp<5
